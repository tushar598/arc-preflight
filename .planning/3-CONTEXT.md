# Phase 3 Context: Integration Tests + Ethers Adapter + Sanctions Data

## Summary

Phase 3 covers three things in parallel:
1. **vitest integration tests** — live Arc Testnet calls proving `preflight()` works end-to-end
2. **Ethers v6 adapter** — `src/adapters/ethers.ts`, symmetric to the Viem adapter
3. **Sanctions data ingestion** — `sync-lists.ts` script + `data/sanctions.json` + GitHub Action on PR merge

---

## Decisions Locked

### Testing

- **Test runner:** vitest (matches requirements.md `^5.0.1`)
- **Network:** Real Arc Testnet RPC (`https://rpc.testnet.arc.network`) — no arc-anvil, no mocking
- **Test structure:** Live integration tests that prove the actual RPC behaviour:
  - Clean address → `safe: true`, `revertReason: null`
  - Blocklisted address (`TESTNET_BLOCKLISTED_ADDRESS`) → `safe: false`, `revertReason: 'Blocked address'`
  - `withPreflight` proxy blocks blocklisted → `PreflightError`
  - `withPreflight` proxy allows clean address through
- **Location:** `packages/arc-preflight/tests/preflight.test.ts`
- **vitest config:** `packages/arc-preflight/vitest.config.ts` — `testTimeout` set high (15 000ms) for RPC latency

### Ethers Adapter

- **Version:** ethers v6 (ESM-friendly, matches `requirements.md`)
- **Location:** `packages/arc-preflight/src/adapters/ethers.ts`
- **Exports (symmetric to Viem adapter):**
  ```ts
  export async function preflight(sender, recipient, provider: JsonRpcProvider): Promise<PreflightResult>
  export function withPreflight(signer: Signer, provider: JsonRpcProvider, options?: PreflightOptions): Signer & { __preflight: true }
  ```
- **Probe mechanism:** Same as Viem — native value send via `provider.call({ from: sender, to: recipient, value: 1 })` with state override for balance
  - ethers v6 uses `Overrides` object; state override is passed via `provider.send('eth_call', [tx, 'latest', stateOverride])`
- **Export from index.ts:** Both `preflight` and `withPreflight` already named in viem adapter — Ethers exports use named sub-exports from the same entry point:
  - Add: `export { preflight as preflightEthers, withPreflight as withPreflightEthers } from './adapters/ethers.js'`
  - _(Different names to avoid collision with Viem exports in the same entry point)_
- **devDependency:** `ethers@^6` added to `packages/arc-preflight/package.json` devDependencies; `peerDependencies` add optional ethers `>=6.0.0`

### Sanctions Data Ingestion

- **Source:** OFAC SDN XML — `https://sanctionslistservice.ofac.treas.gov/api/PublishedLists/download?type=SDN&ext=XML`
- **What to extract:** Ethereum addresses only — from `<alias>` entries where `id_type='Ethereum Address'` (normalised to lowercase `0x…`)
- **Output:** `packages/arc-preflight/data/sanctions.json` — committed in the repo, shipped in npm package
  ```json
  {
    "version": "2026-09-19",
    "source": "OFAC SDN",
    "addresses": ["0x...", "0x..."]
  }
  ```
- **Script:** `scripts/sync-lists.ts` — fetches OFAC XML, parses with regex/DOMParser, writes JSON
- **GitHub Action trigger:** `pull_request` (on merge) — commits updated JSON automatically
  - File: `.github/workflows/sync-sanctions.yml`
- **SDK function:** `checkSanctions(address: Address): boolean`
  - Reads `data/sanctions.json` at import time (static import)
  - Exported from `index.ts` as a standalone function
  - Does NOT automatically run inside `preflight()` — it's opt-in
  - Caller can compose: `if (checkSanctions(recipient)) { ... } else { await preflight(...) }`

## Key Risk

> [!NOTE]
> The OFAC XML endpoint sometimes rate-limits CI fetches. The GitHub Action should include a `continue-on-error: true` on the fetch step and a meaningful commit message if the list is unchanged. If the endpoint is unreachable, the existing `data/sanctions.json` should remain unchanged.
